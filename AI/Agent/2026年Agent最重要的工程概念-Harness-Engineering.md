# 2026 年 Agent 最重要的工程概念：「Harness Engineering」

最近，AI 圈子里又冒出一个新词：Harness Engineering。

**提示词工程（2024）→ 上下文工程（2025）→ Harness Engineering（2026）**

提示词工程是教模型听懂话，上下文工程是让模型看到全貌，Harness Engineering 则是给 Agent 搭一整套能自己干活的工作环境。

最直白的理解：给 Agent（干活的牛「马」）套一个 Harness（马具，让马能拉动东西、真正干活的整套结构）。

这个概念最早从 HashiCorp 联创提出，随后 OpenAI 发布了一篇文章彻底引爆。以下是 OpenAI 文章的核心内容。

---

## OpenAI 的五个月实验：用 Codex 从零构建产品，无人工代码

- 从空的 Git 仓库开始，初始架构由 Codex CLI + GPT-5 生成
- 五个月后：约 100 万行代码，1,500 个 PR，仅 3 名工程师
- 平均每位工程师每天处理 3.5 个 PR
- 产品已在数百名内测用户中投入使用
- **核心理念：不手动编写代码**

## 人类和 AI 如何互动

工程师工作的重点转向了系统、架构和杠杆作用。

当事情不顺利时，解法从来不是"再试一次"或"换个提示词"。工程师要做的是退后一步问：智能体缺什么？是工具、是文档、还是约束？然后把缺的东西补到代码仓库里。

人类几乎完全通过提示词与系统交互。审核工作也逐渐调整为智能体对智能体的方式。

## Harness 工程经验

### 1. 代码仓库是记录系统

**给 Codex 的是一张地图，而不是一本 1,000 页的说明书。**

大型 AGENTS.md 的失败原因：
- 情境是稀缺资源，巨大文件会挤掉关键约束
- 过多指导反而无效，智能体做本地模式匹配而非有意识导航
- 迅速过时，变成过期规则的坟场
- 没法自动检查

解决方案：AGENTS.md 当内容目录（约100行），知识库放在结构化的 docs/ 目录中。

文档结构：
```
AGENTS.md
ARCHITECTURE.md
docs/
├── design-docs/
├── exec-plans/
├── generated/
├── product-specs/
├── references/
├── DESIGN.md
├── FRONTEND.md
├── PLANS.md
├── QUALITY_SCORE.md
├── RELIABILITY.md
└── SECURITY.md
```

专职 linter 和 CI 作业验证知识库更新状况。定期运行的"doc-gardening"智能体扫描过时文档并发起修复 PR。

### 2. 目标是智能体的可读性

从智能体的角度看，运行时无法在情境中访问的任何内容都是不存在的。存储在 Google Docs、聊天记录或人们头脑中的知识都无法被系统访问。

倾向于选择可以完全内化于仓库中推理的依赖项和抽象。"枯燥"的技术由于可组合性、API 稳定性和在训练集里的表现，往往更容易建立模型。

### 3. 规范架构与品味

**通过强制执行不变量，而非对实施过程进行微观管理。**

每个业务域划分为固定层：Types → Config → Repo → Service → Runtime → UI，依赖方向严格验证。通过自定义 linter 和结构测试机械地强制执行。

生成的代码不总是符合人类风格偏好，这也没关系。只要输出正确、可维护、对未来的智能体运行清晰易读即可。

### 4. 吞吐量改变了合并理念

PR 生命周期很短。测试偶发失败通过后续重跑解决。在智能体吞吐量远超人类注意力的系统中，纠错成本低，而等待成本高。

### 5. 熵与垃圾收集

Codex 会复现已存在的模式，包括不理想的模式。建立"黄金原则"直接编码到代码仓库中，定期运行后台 Codex 任务扫描偏差、发起重构 PR。

**技术债就像高息贷款：每天还一点，远比攒到还不起时被迫清算划算得多。**

### 6. 不断提高的自主水平

Codex 已能端到端驱动新功能：
1. 验证代码库状态、复现漏洞、录制故障视频、实施修复
2. 验证修复、录制解决视频、开 PR、回应反馈
3. 检测并修复构建故障、合并更改

## 核心启示

**Agent 不好用，大多数时候不是模型的问题，是你的工程环境的问题。**

自问：
- 架构约束是写在文档里，还是只存在于团队口头约定中？
- 测试能被自动运行，还是需要人手动触发？
- 设计决策有记录，还是散落在三个月前的聊天里？

**每一个想让 Agent 真正干活的团队，最终都会发现，Agent 的瓶颈已经不在模型了，而在你给模型搭的那套环境。**
